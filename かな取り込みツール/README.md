# かな取り込みツール

Figma「フォント作成」ファイルのかなもじページから、グリフを自動で SVG 化して
asteain フォント (asteain.sfd / .ttf / .woff) に収録するパイプライン。
2026-08-22 時点でひらがな・カタカナ 210 字を収録。

## 工程の全体像 (本線 = ルートC)

```
Figma  ── SVG 書き出し (「Include "id" attribute」を有効に) ──▶  1 枚の .svg
  │  ① kana_group_route.py  … 名前で同定・マスク解決・升目正規化
  ▼
グリフsvg/かなもじ/uXXXX_名前.svg + manifest.json   (56×64・マーカーバー付き・図面の記録)
  │  ② kana_import.py       … ffpython で sfd に取り込み (×32 で em2048 へ、字送りは規則で決定)
  ▼
asteain.sfd / asteain.ttf / asteain.woff
  │  ③ verify_font.py / bearings.py / coverage.py … 検証・左右ベアリング実測・未収録一覧
```

REST API を使う版 (ルートA) と、名前が落ちる Copy as SVG 版 (ルートB) も残してある。
詳しくは下の各節を参照。

## 必要環境 (このPCで確認済み)

- Node.js (①)
- Python 3.12 + `pip install skia-pathops fonttools` (②)
- FontForge の ffpython: `C:\Program Files (x86)\FontForgeBuilds\bin\ffpython.exe` (③)
- ImageMagick (任意・確認用レンダリング)

Figma の個人アクセストークン (File content: Read-only で足りる) を、

## 再実行手順 (ッ・ヴ・ー などを描き足したあと)

このフォルダで:

```sh
# ① 構造を取得 (セクション → 行グループ)。
#    ノード ID は作者が描き直すと変わるので、ids を固定で持たず毎回ここで取り直す。
node figma_structure.mjs rows.json

# ② 行グループを SVG で書き出し (rows.json の id を全部渡す)
IDS=$(node -e "console.log(require('./rows.json').rows.map(r=>r.id).join(','))")
node figma_fetch.mjs "/v1/images/MjWgTZUrTpt7BFMZ70W790?ids=$IDS&format=svg&svg_include_id=true" rows_urls.json

# ③ 分割・正規化 (出力先はリポジトリの グリフsvg/かなもじ)
python kana_svg_route.py rows_urls.json rows.json "../グリフsvg/かなもじ"

# ④ フォントへ取り込み (リポジトリ直下の asteain.sfd を更新し ttf/woff を再生成)
#    最後の引数が字送りの規則。family = 家風準拠 (これが本採用)
ffpython kana_import.py ../asteain.sfd "../グリフsvg/かなもじ" .. asteain family

# ⑤ 検証
ffpython verify_font.py ../asteain.ttf
python bearings.py ../asteain.ttf   # 左右対称・はみ出しの実測
```

③は `_rows/` にダウンロード済みの SVG があるとそれを使い回すので、
**Figma を更新したら出力先の `_rows/` を消してから実行する**。
消し忘れると古い字形のまま焼き付く (実際に踏んだ)。
③の出力に `★升目からはみ出し` が並ぶときは、濁点が枠外に出ているサイン。

### 文字の同定のしかた

`(セクション名, 行グループ名, 段)` の 3 つで引く ([kana_resolve.py](kana_resolve.py) の表)。
**列の位置は使わない** — 作者が列を詰めて置くことがあり、五十音の列と一致しないため
(実際、小書きカ行が 6 列目に置かれていた)。段はガイドの升目から
`段 = そのグリフの升目行 − セクションの先頭升目行` で求める。

行を増やしたら [kana_resolve.py](kana_resolve.py) の `BASE_ROWS` / `DAKUTEN_ROWS` /
`SMALL_ROWS` / `SINGLES` に 1 行足すだけでよい。**Figma の行グループ名と表のキーが
一致していることが条件**なので、行の名前は「ア行」「ヷ行」のように付けること。

## 新しい字を足すときの約束事

- グリフは五十音表のガイドグリッドに載せる。**セル = 56×64、原点 (54,444)、
  ベースライン = セル上端+51**。表の (列, 段) 位置がそのまま文字の同定になる。
- **横位置は図面では決めない。** `グリフsvg/かなもじ/` の SVG は升目をそのまま切り出した
  「図面の記録」で、字送りと左右ベアリングは取り込み時に規則で与える。

### 字送りの規則 (2026-08-16 決定・全書体共通)

> **送り幅 = インク幅 + 5 (左右のベアリングを 2.5 ずつ)**

既存 6 書体 (幻字 207/207・アソーグ 216/216・ザイロ 72/72・新笈霜 107/107・
デーレ 179/180・ラテン) を実測して得た家風で、ストローク幅がちょうど 5 なので、
実質 **「中心線スケルトンの左端＝原点、右端＝送り幅」**。丸キャップが左右に 2.5 ずつ
はみ出しているだけ、という意味になる。かなもこれに合わせた＝**仮名プロポーショナル
(いわゆる「P」付きフォント) の類型**を採る。日本語の全角等幅の慣例より、統一フォント
としての一貫性を優先した判断。実測でかなの送りは 49〜52 に収まり、ほぼ均一に見える。

- 濁点・半濁点は**升目の内側に収める** (日本語フォントの作法。ガがカより広くならない)。
  外に出ていると、その字だけ送りが広くなって不揃いに見える。
- 縦書きは縦の送り (vwidth = 2048 固定) で決まるので、横をプロポーショナルにしても崩れない。
- Unicode に無い字 (小キ・小サ・小yi など 18 音) は表の cp を `N` にしておくと
  `unmapped_名前.svg` として SVG 保存だけされ、フォントには入らない (現行方針)。
- 行グループを Figma 上で移動・作り直ししても、①で毎回 rows.json を取り直すので
  追従する。ノード ID をどこかに固定で書かないこと。

## 収録サンプル (index.html) の未収録判定について

サンプルは本来 `asteain.woff` の cmap を直接読んで「未収録」を判定する
(常に現物と一致するのでこれが本筋)。ただし **`file://` で直接開くと fetch が弾かれ、
判定ごと無効になる** — 豆腐にも灰色にもならず、記号がそのまま代替フォントで出てしまう。

そのため `kana_import.py` が `font_coverage.js` (収録コードポイントの範囲一覧) を
毎回書き出し、index.html は fetch が失敗したときだけそれを読む。
`<script src>` は file:// でも読めるため。**手で編集しないこと** (再ビルドで上書きされる)。

## ハマりどころ (2026-08 実測)

- **REST の `geometry=paths` はプランのクォータを即座に食い潰す** (429 /
  Retry-After が数日単位)。パスデータはそちらからは取らず、**画像エクスポート API
  (`/v1/images?format=svg`) を使う**。全行を 1 呼び出しでまとめて出せる。
- Figma の SVG 書き出しは、内側揃えストロークを `<mask>` で表現する。
  kana_svg_route.py が「ローカル座標のままパス∩マスク→配置変換」の順で解決する
  (変換後に交差させると空になる)。中心線ストロークに簡約された枠線矩形 (ロ・゜) や
  回転 rect、グループ外にはみ出した半濁点の接着も対応済み。
- **線 (stroke) を塗りとして扱わないこと。** Figma はループのある字 (ぬ・ね・は・ほ・ま・
  む・よ・る・ゐ・ゑ など) を `<path stroke="black" stroke-width="5">` の中心線として
  書き出す。これを `d` の塗りだと解釈すると**輪の内側まで埋まる**。
  `path_region()` が `pathops` の `Path.stroke()` で線を展開する
  (`stroke()` は CONIC を吐くので `convertConicsToQuads()` を挟まないと `simplify()` が落ちる)。
  端点・角は SVG の既定 (butt / miter) に従う — Figma は stroke-linecap/linejoin を書き出さない。
  ※ Figma 側で autoFlater をかけて塗りに変換しておけばこの経路は通らないが、
    **かけなくても正しく取り込めるようにしてある**ので、元データを平坦化する必要はない。
- ffpython の SVG 取り込みは **線を展開しない** (`d` を塗りとして読む)。
  FontForge 側で直すなら `glyph.stroke("circular", 幅, "round", "round")` が要る。
- ffpython の SVG 取り込みは viewBox 高さ 64 → em2048 にちょうど ×32 で載る
  (既存グリフと同じ「ベースライン+6」)。kana_import.py が 1 字目で校正して検算する。

## ルートC: id 付き SVG 書き出し（★これが最良。2026-08-22 の 210 字収録で使用）

Figma の**書き出しパネルで SVG を選び、設定 (…) の「Include "id" attribute」を有効に**して
書き出したもの。ひらがな・カタカナ・記号・ガイドを 1 ファイルにまとめて出してよい。

```sh
python kana_group_route.py "<書き出した.svg>" "../グリフsvg/かなもじ"
ffpython kana_import.py ../asteain.sfd "../グリフsvg/かなもじ" .. asteain family
ffpython verify_font.py ../asteain.ttf
python bearings.py ../asteain.ttf
python coverage.py ../asteain.ttf
```

このルートが強いのは 2 点:

- **グループ名が id として残る**ので、(セクション名, 行グループ名, 段) で同定できる。
  列の並びに一切依存しないので、作者が配置を変えても壊れない。
- **ガイドも一緒に書き出せる**ので、升目の原点を推定ではなく**厳密に決定**できる。
  ガイドの市松模様 (28×26 の四角) の 1 個目が升の左上ちょうどに置かれている性質を使う
  (縦は「+26 の関係」が一意に効くので先に縦を決め、その行の x から横を決める)。

期待する入れ子 (名前はこの通りにしておくこと):

```
Group 1
├ ひらがなガイド / カタカナガイド   ← 名前に「ガイド」を含むものは捨てる
├ カタカナ
│  ├ 基本カタカナ  → ア行・カ行…ワ行・ン
│  ├ 濁点付き      → ガ行・ザ行・ダ行・バ行・パ行・ヴ・ヷ行
│  └ 小書き        → ァ行・小書きカ行・サ行…ラ行・ン(=小ン)
├ ひらがな
│  ├ 基本ひらがな   → あ行…わ行・ん
│  ├ ひらがな濁点付き → が行・ざ行・だ行・ば行・ぱ行・う゛(=ゔ)
│  └ ひらがな小書き  → あ行・か行・た行・や行・わ行
└ 記号             → ゛ ゜ ・ ー
```

- **記号セクション**は行ではなく、直下の図形を**レイヤー名でそのまま**引く。
  名前を字そのもの (`「` `。` `ゝ` `々` `〜` など) にしておけば、描いた時点で拾える
  ([kana_resolve.py](kana_resolve.py) の `SYMBOLS` に 62 件登録済み)。
  **全角の丸括弧 `（）` は U+3000-303F ではなく「全角形」ブロック (U+FF08/FF09) にある。**
  同様に `！？：；～［］｛｝` なども全角形。登録済みなので描けば拾える。
### 描かなくてよい字 (取り込み時に自動生成する)

[kana_import.py](kana_import.py) が毎回作り直すので、Figma に描く必要はない。
**同じコードポイントを図面から取り込んだ場合はそちらが優先**され、自動生成は行われない。

| 字 | 作り方 |
| --- | --- |
| 全角スペース U+3000 | 輪郭なし・送り 56 単位 (= 升目 1 つぶん。ASCII の半角スペースは 32 単位) |
| 結合用濁点・半濁点 U+3099 / U+309A | 単独版 U+309B / U+309C の複製。送り 0 で直前の字に重なる位置 |
| 全角形 U+FF01〜FF5E (94 字) | ASCII U+0021〜007E への**参照**。送り 56 単位でインクを中央に置く |
| 〈 U+3008 / 〉 U+3009 | デーレ文字 U+F2F8B / U+F2F8C が同じ形なので、その**参照**。字送りも借り元のまま |
| `font_coverage.js` | フォントではなく、収録コードポイントの一覧。index.html が **file:// で開かれたとき**に使う (下記) |
| 豆腐 □ U+25A1 と `.notdef` | 家風の枠 (幅 5 のモノライン・インク 45×50)。収録サンプルが未収録の升に出す □ を**代替フォントに描かせない**ため。混ざると其の升だけ行の高さが変わり、リッチ表示で枠がガタつく |

全角形を別に描かないのは、**このフォントではラテンとかなの寸法系が同じ**だから。
実測で ASCII の `( ) [ ] ?` はかなと同じ縦の帯 (y 1〜51) に載っている。
普通の日本語フォントが全角形を描き起こすのは寸法系のずれを直すためなので、
ここではその必要がない。参照なので `(` を描き直せば `（` も自動で追従する。

- 例外: ASCII の `,` はベースラインより下に出る設計 (y −9.8〜10.2) なので、
  全角形 `，` もそのまま沈む。日本語では `、` を使うので実害は薄いが、
  `，` を正しく使いたくなったら別に描くこと。
- **結合用の濁点・半濁点 (U+3099/309A) は描かなくてよい。** 取り込み時に、単独版
  (U+309B/309C) から「送り幅 0・直前の字に重なる位置」の複製を自動生成する
  ([kana_import.py](kana_import.py) の `make_combining_marks`)。位置は実際の合成字から
  逆算した「濁点の右端 = 基字のインク右端」に合わせてある。
- 行グループ名の頭の「小書き」は自動で外す。「う゛」は ゔ、「ウ゛」は ヴ として扱う。
  小書きセクションの「ン」は小書きのン (U+1B167) として扱う。
- 濁点付きの行が「基字行のインスタンス＋濁点」になっていてもよい (段でまとめるので合体する)。
- インクは**黒だけ**を拾う。ガイドの色付き図形は無視されるが、
  字の一部がうっかり黒以外になっていると落ちるので注意
  (実際に #020000 という惜しい色が 2 つ見つかったことがある)。

## ルートB: Copy as SVG (API を一切使わない・2026-08-16 の 117 字収録で使用)

Figma 標準機能だけで完結する。**REST が枯れていても使え、こちらの方が確実。**

1. かなもじページで 3 セクション (基本カタカナ・濁点付き・小書き) を選択
   ※ガイドは選ばなくてよい
2. 右クリック →「Copy/Paste as」→「**Copy as SVG**」
3. テキストファイルに貼って `.svg` で保存
4. `python kana_page_route.py <その.svg> "../グリフsvg/かなもじ"`
5. あとは④⑤ (kana_import.py → verify) は同じ

**Copy as SVG はグループ名を落として平坦化する**ので、このルートでは名前が使えず、
五十音表の**升目の (列, 行)** だけで文字を同定する
([kana_resolve.py](kana_resolve.py) の `COL_TO_ROW` / `EXTRA_CELLS`)。
升目の原点は、図形の下端がベースライン (51)・左端が 5 に集まる性質から自動で割り出す
(実測 124/136 升が一致したので、まず外さない)。

したがって **列の並びが五十音順であること**が前提になる。列を入れ替えたり、
新しい列を足したりしたら `COL_TO_ROW` を直すこと。現在の配置:

| セクション | 升目行 | 列 |
| --- | --- | --- |
| 基本カタカナ | 0–4 | 0〜9 = ア〜ワ行、10 = ン・゛・゜・中黒・長音 (段順) |
| 濁点付き | 6–10 | 0 = ヴ (う段のみ)、1〜5 = ガザダバパ行、9 = ヷ行 |
| 小書き | 12–16 | 0〜9 = ァ〜ワ行 (51 音のうち 50 音。小ンのみ未描画) |

### ひらがなを収録するとき

**カタカナとは別に Copy as SVG する**こと。ひらがなガイドはカタカナガイドと
升目の原点が違うので、一緒に選択すると原点の自動検出が食い違う。

```sh
python kana_page_route.py <ひらがなの.svg> "../グリフsvg/かなもじ" hiragana
```

対応表は [kana_resolve.py](kana_resolve.py) の `*_HIRA` 一式に用意済み
(コードポイント付き 96 字ぶん、重複衝突なしを確認済み)。カタカナとの違い:

- **や行イ段の古字はコードポイントが無い** (エ段は 𛀁 U+1B001、わ行ウ段は 𛄟 U+1B11F)
- **小書きは 51 音中 16 音しかコードポイントが無い** (ㇰㇱㇲ… のアイヌ語用はカタカナ専用)
- **ゔ はあるが、わ行の濁点 (ヷヸヹヺ 相当) はひらがなに無い**
- **゛ ゜ ー ・ はカタカナと同じコードポイントを共有する**。ひらがな側でも描くと
  カタカナ側の字を上書きするので、どちらの字形を採るか決めてから描くこと
- ゝ ゞ ゟ (繰り返し記号・合字より) はひらがな側にある

配置 (どの列にどの行を置くか) は今のカタカナと同じ並びを仮定している。
違う並びにするなら `COL_TO_ROW_HIRA` を直す。

## ルートA (REST) が使えないときの受け渡し

**Figma の REST は「ファイル読み取り」と「画像書き出し」が同じ予算を共有していて、
使い切ると数日単位 (実測 4〜5 日) の 429 になる。** 構造取得 (`?depth=` や `?ids=`) は
特に重いので、①は用が済むまで何度も叩かないこと。`/v1/files/…/nodes` は
別枠だが先に枯れやすい。枯れているかは Retry-After ヘッダで分かる。

そのときは Figma の標準機能だけで渡せる:

1. かなもじページで Ctrl+A (全選択)
2. 右クリック →「Copy/Paste as」→「**Copy as SVG**」
3. テキストファイルに貼って `.svg` として保存

全選択なので**ガイドの升目も一緒に入り、座標系が 1 つに揃う**ため、
ノード ID も absoluteBoundingBox も要らずに全グリフを拾える
(この入力を読む処理は、実物の SVG を見てから書く)。

## 濁点付きを基字に追従させる (Figma 標準機能)

プラグインは不要。**コンポーネント**がそのための機能。行ごとにやると 5 回で済む:

1. カ行グループを選択 → Ctrl+Alt+K でコンポーネント化
2. ガ行の中の基字 5 つを削除 (濁点は残す)
3. カ行のインスタンスを 1 つ作ってガ行に入れる
4. サ行→ザ行、タ行→ダ行、ハ行→バ行・パ行 も同様

字ごとの名前 (ガ・ギ…) を残したいなら、25 字を複数選択して右クリック →
「Create multiple components」で一括コンポーネント化してから中身を差し替える。
取り込み側 (kana_svg_route.py) は、**行ごとインスタンスでも字ごとでも**
拾えるようにしてある (1 升に収まらない塊は中に降りる)。

※ Figma の「バリアブル」は色・数値・文字列・真偽値しか入らないので字形には使えない。
